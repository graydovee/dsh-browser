# Agent Note: 浏览器通用输入层

Status: implemented

[English](2026-10-21-browser-input-layer.md) | **中文**

## 问题

浏览器桥此前能读页面、能操作快照里编过号的元素，但凡是没暴露语义角色的目标都到不了：画布、SVG 菜单、富文本编辑器、拖拽面板。缺少的是指针移动与按下/抬起、组合键、向自持文档模型的编辑器写入文本、剪贴板传输和文件输入。这是缺少输入层，不是缺少某个应用适配。

## 决策

**只做一层通用输入，不写应用特判。** 键盘、指针、文本、剪贴板、文件都按「元素身份或坐标」寻址，任何页面用同一组参数。实现里不出现域名、组件类名或编辑器实现的判断，应用配方只放在文档里。

**两条投递通道，一个模型契约。** 元素寻址、纯文本、粘贴事件和普通点击留在内容脚本，不需要调试器。真实指针事件、滚轮手势、组合键、光标插入、系统粘贴和文件附加需要浏览器进程，走 `chrome.debugger`。结果标注通道（`(trusted)` 或 `(synthetic)`）；平台无法投递时返回稳定的 `input-unavailable`，而不是静默失败。

**输入状态按标签页保存。** `browser_press { action: down|up }` 按住修饰键，`browser_click { action: down|up }` 按住鼠标键，后续手势自动携带它们。于是 Shift+点击、Cmd+拖拽、按下-拖动-抬起无需专门的组合工具。导航、关标签页和附加丢失都会重置状态。

**坐标是 frame 局部的。** 指针动作寻址目标 frame 视口内的点；内容脚本沿 `window.parent` 上报每层 frame 的位置链，后台求和换算成标签页视口坐标。跨源祖先无法访问 `frameElement`，因此坐标类动作在那里失败，而元素寻址与粘贴事件照常可用。

**每个标签页一个调试器，共享使用。** 一个标签页只能被附加一次，因此由 broker 持有按标签页的会话、统计持有它的功能（开发者工具与输入），开发者工具停止时立即释放、输入空闲一段时间后释放。真实输入在同意面上就是普通动作：与 click/type 一样按逐次审批、可信来源和完全访问规则处理，因为它并没有给页面 DOM 点击之外的新权限。独立同意面只保留给开发者工具组（任意页面 JavaScript、DOM 写入、网络抓包）。

**剪贴板有两条不同的路径。** 默认是用 `DataTransfer` 构造粘贴事件：所有支持的浏览器都能用，不碰用户剪贴板，HTML 在进入页面前净化。写系统剪贴板在 Chrome 用打包的离屏文档（MV3 worker 没有 DOM），Firefox 用事件页的隐藏可编辑节点；随后用平台粘贴快捷键覆盖只认真实粘贴的应用。

**文件附加不读文件内容。** 内容脚本给 file input 打一次性标记，后台经 CDP 解析该节点，浏览器进程读取调用方给出的路径。扩展从不打开文件。

## 影响

- `browser_snapshot`、`browser_click`、`browser_type`、`browser_press`、`browser_scroll`、`browser_follow_tab` 增加参数；新增两个工具（`browser_clipboard`、`browser_upload`）。
- Chrome 增加 `clipboardWrite` 与 `offscreen` 权限以及一个打包的离屏页面；Firefox 清单不变并降级。
- 输入不会激活标签页、聚焦窗口或移动系统鼠标。`browser_follow_tab { activate: true }` 是唯一显式切前台入口，截图仍要求活动标签页。
- 附加调试器会显示 Chrome 提示条，并让该标签页暂时不能开 DevTools；空闲释放把代价限制在一次输入序列内。
- 附加可能改变视口高度（提示条占位）：坐标应在附加之后测量，broker 的空闲窗口让这一点成为默认。
- macOS 的编辑快捷键是应用菜单命令：全选、复制、粘贴、剪切、撤销、重做只有在 key-down 里指明命令名时才生效，因此 macOS 的 Meta 组合键会携带 `commands`。
- 滚轮由合成器驱动；后台或被冻结的页面永远不会应答。工具会前置拒绝并给出 `follow_tab { activate: true }` 指引，而不是等到超时；活动页面上可正常滚动。
- 截图来自合成器：标签页必须是活动页且窗口聚焦，否则可能拿到过期帧。工具会拒绝未聚焦窗口；被遮挡但已聚焦的窗口仍属尽力而为。
